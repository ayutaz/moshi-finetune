## 1. 何をしようとしたか

J-Moshi-ext を、つくよみちゃんの声で話すよう追加学習する。そのために対話 script を共有する
2 つのデータセットを作り、**チャンネル A（つくよみちゃん役）の音声だけ**を変えて比較した。

| | チャンネルA | 長さ |
| --- | --- | ---: |
| **V-real** | つくよみちゃんコーパスの**実録音**（train 分割 72文） | 8.67 分 |
| **V-tts** | M2 で採用した **speaker inversion TTS** の合成音 | 9.47 分 |

script、分割、話者 B の音声、タイムライン、base checkpoint、依存関係はすべて同一である。

### M3 は overfit の工程ではない

実験全体（ブランチ名、M4 のタイトル）は「voice overfit」を掲げているが、**M3 はその前段の
control** である。計画は 2 段階に分けている。

| | 段階 | 学習率 | 位置づけ |
| --- | --- | --- | --- |
| **M3** | Voice **control** | tempformer / depformer とも `3e-5` | 過去に実際に動いた条件の再現。壊れていない基準を作る |
| M4 | Voice **overfit** | tempformer `3e-5` 固定、depformer を `6e-5` → `1e-4` | 意図的に声側を強める |

計画は「最初から V2/V3 を実行しない。V0/V1 で mode collapse がなく、過去 control と同程度の
対話能力を確認してから学習率を上げる」と明示している。

なお **`3e-5` は「過去に動いた control」ではあるが、文献上は fine-tuning の値ではない。**
J-Moshi 論文ではこれは**事前学習**の学習率で、fine-tuning は tempformer `2e-6` / depformer `4e-6`
である。加えて `3e-5` は `finetune.py:166-176` の argparse 既定値そのもので、warmup も既定 0 だった。
詳細は §6。

## 3. 何が起きたか

### loss は下がり、モデルは黙った

> **訂正（2026-08-25）**: 本節の loss に関する 2 つの記述を訂正した。
> (a)「11.39 → 1.73 へ単調に減少」は **epoch 平均でのみ真**である。
> (b) 過去の depformer-only 崩壊（audio loss `6.88 → 1.02`）の「再現」という読みは**撤回**した。

**epoch 平均の** train loss は両 run とも **11.39 → 1.73** へ単調に減少した。同じ期間に生成は劣化した。

| run | epoch | train loss（epoch 平均） | 劣化生成 / 50 | held-out 有声フレーム中央値 | 話者らしさ勝ち / 10 |
| --- | ---: | ---: | ---: | ---: | ---: |
| control | — | — | 2 | 125 | — |
| V-real | 1 | 11.39 | 50 | 9 | 0 |
| V-real | 2 | 5.88 | 15 | 228 | 0 |
| V-real | 3 | 3.94 | 9 | 38 | 2 |
| V-real | 4 | 2.41 | 17 | **0** | 0 |
| V-real | 5 | **1.73** | 29 | **0** | 1 |
| V-tts | 1 | 11.18 | 18 | 66 | 1 |
| V-tts | 2 | 5.62 | **1** | 214 | 3 |
| V-tts | 3 | 3.93 | 4 | 142 | **5** |
| V-tts | 4 | 2.31 | 15 | 120 | 4 |
| V-tts | 5 | 1.62 | 6 | 108 | **5** |

**訂正: 表の loss は各 epoch の 9 step の平均であり、step レベルでは単調ではない。**
44 の遷移のうち **v-real で 18（40.9%）、v-tts で 17（38.6%）が増加**している。
さらに各 step 値は gather されておらず、**8 対話中 1 対話のサンプル**である
（当時の学習ループが gather されていない `total_loss.item()` を印字していた。per-device batch 1・grad-accum 4・world_size 2。M3-R 第 1 段 1-6 で gathered 平均に修正済み）。
同一台本の両 arm で step 1 の text loss が 7.588 対 7.160 と食い違うのがその直接証拠である。

**V-real は最良の loss で音を出さない。** epoch 4 以降、held-out の有声フレーム中央値が 0 になる。
テキストだけでなく音響でも何も出力していない。

**訂正: この崩壊の証拠を loss に置くことはできない。**
撤回前の本文は、過去の depformer-only 実験の崩壊（audio loss `6.88 → 1.02`、`plan.md:93`）と
M3 の `6.82 → 1.03` の一致を「再現」と読んでいた。しかし audio loss は `ln(2048) = 7.625` から
始まる量であり、**未学習時はどの run もほぼ chance から始まる**。過去の**成功** run も
`12.53 → 1.24` である（`plan.md:84`）。**始点も終点も、成功 run・失敗 run・M3 の 3 者を
区別しない。**

崩壊の証拠は生成トークン側にある。550 個の生成トークンから話者 A の audio codebook 0 を
集計すると、held-out の distinct 中央値は v-real で **48 → 81 → 52 → 5 → 5** と推移する。
**劣化は epoch に対して単調で、両 arm に独立に再現している。**
固定された形式欠陥は「水準」を決められても「傾き」を決められないので、これは指標の
アーティファクトではなく実在する崩壊である。

この実験が「loss だけで判定しない」と最初に決め、崩壊検出・話者類似度・turn-taking を
別々に測る設計にしていたため、**loss 上は成功に見えるものを不合格と判定できた**。

### 声が寄ったかどうかは判定できていない

> **訂正（2026-08-25）**: 撤回前の本文は「最良の腕（V-tts epoch 3 / 5）で 5/10 にとどまる。
> ほぼコイン投げであり、声が寄ったとは言えない」と書いていた。**この読みは撤回する。**

条件 4 の事前登録基準は 3 つある（`m3/DATASET_SPEC.md`、`m3-speaker-likeness.json` の
`criteria_fixed_before_measuring`）。

| 基準 | 内容 | v-tts/epoch3 |
| --- | --- | --- |
| 方向 | `mean_delta` > 0 | +0.0321 **達成** |
| 効果量 | `mean_delta_full_set` ≥ **+0.02** | **+0.0321 達成**（10 件中 9 件が採点可能）|
| 一貫性 | 10 文中 **8 文以上**で control より高い | 5 / 10 **未達** |

**落ちたのは一貫性基準だけである。** 効果量基準は満たされていた。
v-tts/epoch4（+0.0666、採点可能 5）と v-tts/epoch5（+0.0628、採点可能 6）も数値上は
超えているが、採点可能数が半分近く落ちているぶん v-tts/epoch3 ほど強くない。
v-real/epoch5 の +0.0246 は採点可能 1 件の見せかけで、これは次節で扱う。

**一貫性基準 8/10 は検出力を持たない。** 片側符号検定で α = 0.0547、真の勝率が 0.70 でも
検出力は **0.383**、0.80 でも 0.678 である。10 腕を同じ 10 文で判定しているので family-wise の
偽陽性上限は 0.43。**「効果なし」と「検出力不足」が分離できていない。**

**さらに、8/10 はこの測定系では構造的に達成困難だった。** 期待勝率 0.8 を得るには、
per-clip の対差が自身の σ に対して 0.84 以上でなければならない。効果量基準の +0.02 で
それを満たすには対差の σ が **0.024 以下**である必要がある。
その対差の σ は出荷済み JSON に記録されていない —— それ自体が欠陥である —— が、
control の held-out 絶対 cosine だけで **SD 0.1644**、範囲 0.1398〜0.5599 であり、
対差の σ が 0.024 以下に収まるとは考えにくい。
実際 v-tts/epoch3 は採点可能 9 件中 5 勝で、これは対差の σ が平均差 +0.0321 より
大きいことと整合する。
**事前登録した効果量基準と一貫性基準は、この測定系では同時に満たせない。**
小さいが実在する平均差を拾うために効果量を +0.02 に置きながら、
一貫性基準はその大きさの差では通れない値に置いていた。

**較正帯も絶対値も持たずに判定していた。**

| | mean | median | min | max |
| --- | ---: | ---: | ---: | ---: |
| 対象話者の較正帯（test 10 録音の leave-one-out）| **0.8166** | 0.8175 | **0.7405** | 0.8780 |
| control（J-Moshi-ext）の held-out 絶対 cosine（n = 10）| **0.3728** | 0.3681 | 0.1398 | 0.5599 |

control から較正帯の下端（0.7405）まで **0.3677** ある。効果量基準の +0.02 はその **5.4%**、
v-tts/epoch3 の +0.0321 でも **8.7%** にすぎない。
**「control より 0.02 高い」は「対象話者に寄った」を意味しない。**
`CLAUDE.md` は「0.74 の within-group 類似度は、実人間が 0.70 を取ると知るまで何も意味しない」と
書いている。条件 4 はこの帯を持たないまま判定されていた。

〔実測の出所〕較正帯は検証記録 §5.3。control の絶対 cosine は本訂正で
`tools/speaker_similarity.py` を同一経路（ECAPA / voiced 抽出 / RMS 正規化 / 同一 centroid）で
実行して得た。出荷済みの `m3-speaker-likeness.json` は **delta しか記録しておらず**、
絶対 cosine も per-clip σ も持たない。この 3 項目の出力必須化は
[M3-R 実行計画](./j-moshi-tsukuyomi-ojousama-m3r-plan.md) 第 1 段 1-3 で行う。

**したがって正しい記述は「声は寄らなかった」ではなく「寄ったかどうかを判定できる測定系が
なかった」である。**

### 崩壊した腕ほど「声が似ている」ように見える

`tools/speaker_similarity.py` は自身の docstring で警告している ——
「平坦で過度に平滑化された出力の方が、聴き手が本人らしいと感じるものより高得点になりうる」。

実際にそれが起きた。`v-real/epoch5` は、**両者が音を出した clip だけ**を平均すると **+0.2463** で、
実験中で最強の話者類似度に見える。実体は **10 件中 1 件のみ**から出た数字で、
残り 9 件は音を出していない。固定分母では **+0.0246**、勝ちは 1/10 である。

この誤報を防ぐため、以下を実装した。

- `paired_comparison_over_fixed_set` — 生き残りだけの平均と固定分母の平均を**両方**返し、
  `mean_delta` という曖昧な名前を**存在させない**
- `tools/likeness_guard.py` — 条件 3 を落ちた腕は条件 4 を通せないインターロック

### turn-taking は基準線が成立していない

> **訂正（2026-08-25）**: 撤回前の本文は「**fine-tuning はモデルを『より答えるように』した**」と
> 結論していた。**この読みは撤回する。**

固定 30 会話で、**control（J-Moshi-ext 自身）が 16 会話で一度も応答しない**。
一方、V-real / V-tts の多くの腕は 30/30 で応答する。

| 腕 | 応答した会話 / 30 | 応答遅延（フレーム） |
| --- | ---: | ---: |
| control | 14 | 23.5 |
| V-tts epoch 2 | **30** | 24.6 |
| V-tts epoch 5 | **30** | 25.9 |
| V-real epoch 5 | 22 | 33.5 |

**訂正: その control 自身が general30 で壊れている。**〔実測〕
30 会話中 **16 会話**で話者 A の audio codebook 0 の distinct がちょうど 4 で、
最頻トークンが 124 フレーム中 113 回を占める。そのトークン `1316` は無音である ——
話者 B が教師強制で無音の held-out prompt set において、user codebook 0 の **91.1%** が `1316`
であることで独立に確認した。同じ control は held-out / seen では distinct 57 / 65・退化 0/10 で
健全である。

つまり「control が 14/30 でしか応答しない」は、**control が general30 で退化している状態を
測った数字**である。**比較の基準線が成立していない。**
fine-tuned 腕が 30/30 で応答したことは事実として残るが、それを「fine-tuning がモデルを
より答えるようにした」と読むには、壊れていない基準線が要る。M3 にはそれがない。

音声 prompt set（相手が無音）では劣化した腕が黙り、general30（相手が話す）では全腕が答える。
この 2 つが矛盾しないこと自体は変わらない —— **劣化した腕は無音の相手に対してだけ黙る**。

## 4. 採用 checkpoint: なし

条件 3・4 のいずれも満たす腕がないため、M4 へ渡す checkpoint を採用しない。

最も惜しい腕は **`v-tts/epoch2`**。

- 劣化生成 **1/50**（control の 2/50 より良い、全腕で最良）
- held-out 10/10 が採点可能
- 30/30 で応答

ただし **話者らしさは -0.1249** で control より遠く、条件 4 を満たさない。
そして **export していない**。回収したのは epoch 3 と 5 のみで、インスタンスは破棄済みである。

**訂正で判明: v-real 側の epoch 2 も失っている。**〔実測〕生成トークンの再集計では
`v-real/epoch2` は held-out の distinct 中央値 **81** で control（57）を上回り、
general30 で退化 **0/30**（control は 17/30）である。
**両 arm とも epoch 2 が頂点で、両方とも export していない。**
M3-R は全 epoch を export する。

## 5. 原因の読み — 全面撤回

> **訂正（2026-08-25）**: 撤回前の本文は「**データ量が主因と考えられる**。V-real の話者 A は
> 8.67 分・72 文で、過去に成功したあみたろ実験 189.9 分のごく一部にすぎない。この量に対して
> 5 epoch・`3e-5` は強すぎる」と書いていた。**段落全体を撤回する。**

**比較対象を取り違えていた。** `plan.md` の同じ表の中で、2 つの数値は別の行に置かれている。

| `plan.md` の行 | 項目 | 値 | 何のデータか |
| --- | --- | ---: | --- |
| `:75` | 話者原音 | **189.9 分** | **Irodori-TTS の学習コーパス** |
| `:77` | 合成対話 | **31.7 分** | **過去の Moshi 学習データ** |

M3 の Moshi 学習データは `m3-dataset-agreement.json` で v-real **27.83 分**である。
**like-for-like の比較は 27.83 / 31.7 = 87.8% であって、撤回前の本文が挙げた比率ではない。**
189.9 分は Moshi にではなく TTS に投入された量であり、M3 の Moshi 学習データと並べる数字ではない。

さらに、過去の成功 run は **65 steps・loss 1.24** まで下げて崩壊していない（`plan.md:83-84`）。
M3 は **45 steps・1.72886** である。**過去の方が多く最適化して低い loss に着地し、
壊れていない。** 「この量に対して 5 epoch・`3e-5` は強すぎる」は、
**このプロジェクト自身の記録と矛盾する。**

### 原因は未特定である

**M3 は次の 3 つを同時に振っており、どれが効いたのか分離されていない。**

| 同時に振った変数 | M3 の値 | 比較対象 |
| --- | --- | --- |
| **データ構造** | A は 1 対話に 1 回だけ発話（3 turn / 対話）。重なりなし。A の 68.8% が無音。系列長 21.0 秒 | 過去成功 run は 6.12 turn / 対話。~~Kyutai 公式の推奨系列長は 100〜300 秒~~ ← **誤読。撤回した**（`300` は README に存在せず `duration_sec` は上限の指定。過去の成功 run は 19.02 秒。[監査](./j-moshi-tsukuyomi-ojousama-m3r-dataset-audit.md) §2） |
| **学習率** | tempformer / depformer とも `3e-5`、warmup 0 | `3e-5` は J-Moshi の**事前学習**の値。fine-tuning の文献値は `2e-6` / `4e-6` |
| **更新範囲** | 全パラメータ（8.37B） | Kyutai 公式の既定は LoRA。過去のお嬢様 run は tempformer-only で成功 |

現時点でもっとも整合する機序は「**loss を下げる最短経路が無音だった**」である。
台本は全 80 対話が B-A-B で、非発話チャンネルはデジタル無音なので、
**text が pad であることと話者 A が無音であることが 98% の精度で同値**になる。
モデルには「pad ⇒ 無音を出す」という決定的な近道がある。
**ただしこれも仮説であり、M3 のデータからは確定できない。**

第 4 の未統制要因として、**text stream に既知要件の脱落がある。**
`--no_whitespace_before_word`（`README-ja.md:109` と `README.md:112` が要求）が指定されず、
実データで裸の `▁` が発行 text token の **45.5%** を占めた（フラグ付きなら 3.6%）。
これは row 0 だけの欠陥で audio 側の崩壊軌跡を説明しないが、
base text loss は total の 52.2% を占めるので無視はできない。修正は M3-R 第 2 段 2-1。

### 「実音 vs 合成音」も分離できていない

> **訂正（2026-08-25）**: 撤回前の本文は「モデルが耐えたのは合成であることではなく、
> **その均質さかもしれない**」と留保していた。**留保では足りない。**

V-tts の話者 A 教師音声 80 ターンを、対象話者と同じ centroid に対して測ると
mean **0.7213**、対象話者の較正帯（min 0.7405）の**内側にあるのは 35 ターンだけ**である。
発話長は同等（7.10 秒 vs 実話者 6.77 秒）で交絡ではない。
参考として V-real の教師音声（コーパス原音 90 件）は mean 0.8045、帯内 82/90 である。

**V-tts 腕は学習前から天井が対象話者に届いていない。
この腕で対象話者に到達することは原理的に不可能だった。**
したがって「V-tts が耐えた」ことから実音 vs 合成音について言えることは何もない。
この比較は M2 まで戻らない限り成立しない。

## 6. やり直しの選択肢 — 全面改訂

> **訂正（2026-08-25）**: 撤回前の表は 4 案（A: epoch 削減 / B: `1e-5` / C: コーパス申請 /
> D: 更新範囲）を並べ、**案 A と B を推していた**。原因診断が撤回されたため、
> 案 C の根拠は消滅し、案 A と B の順位も文献に照らして下がる。

| 案 | 内容 | 訂正後の評価 |
| --- | --- | --- |
| **新** | **データ構造を直す**（ルームトーン、重なり、A のターン数、系列長）| **最優先。** 最有力機序「loss を下げる最短経路が無音だった」に直接効く唯一の手 |
| **新** | **計器を直す**（音響崩壊指標、較正帯、条件 4 の再設計、loss 内訳、seed）| **blocking。** 直さずに再走すれば、**再走の結果も同じ理由で判定できない** |
| B′ | 学習率を **`2e-6` / `4e-6`** へ | 案 B の方向は正しいが不足。**`1e-5` でも文献値の 2.5〜5 倍**である。warmup も入れる |
| D | 更新範囲を狭める（tempformer-only 等）| 文献上は有効（LoRA・部分凍結は忘却が少ない）。ただし**次の変数として保留** —— データと LR を直した control を先に取る。`--parameters_to_finetune` は実装済み、LoRA は本リポジトリに未実装 |
| A | epoch を 1〜2 に減らす | **文献上もっとも弱い。** 破滅的忘却は更新パラメータ数と step 数の**同時べき乗則**であり、**early stopping では回避不能**である |
| C | 寄せ集めコーパス（約1,500台詞）を申請 | **根拠撤回。** 「量が主因」が誤りだった以上、追加コーパスを求める理由がない。like-for-like のデータ量は過去成功 run の 87.8% である |

**採用した順序は [M3-R 実行計画](./j-moshi-tsukuyomi-ojousama-m3r-plan.md) にある。**
第 0 段（記録）→ 第 1 段（計器）→ 第 2 段（データ）→ 第 3 段（ローカル計測）まで課金ゼロで、
GPU は第 4 段だけである。再走は **V-real 1 腕のみ**とする —— V-tts の教師音声は較正帯の外なので、
その腕に GPU を使っても既知の null を買うだけである。

やり直す前に **全 epoch を export する**こと。今回は epoch 3・5 しか回収せず、
両 arm の最良である epoch 2 を失った。

**学習率を上げる（overfit 方向）のは順序が逆である。** control が成立していない状態で
強めれば、より速く同じ崩壊に到達する。計画も「両方不合格なら学習率を上げず、M2 または
dataset 構築へ戻る」と定めている。

## 7. 満たせなかったもの

| 項目 | 状態 | 理由 |
| --- | --- | --- |
| eval loss | **消失** | 評価ループ自体は毎 epoch 走っていた（両 nohup に `Running evaluation` が 5 回）が、**loss は 1 つも出力されていない**。当時のコードは W&B 経由でしか出力せず、M3 は W&B を使っていない。dq16 重みも削除済みで再計算不能。stdout への出力は修正済みで M4 以降は残る。学習中の loss 内訳 4 項目も、M3 当時は `if args.with_tracking:` の内側にあり 10 回分すべて破棄された。**M3-R 第 1 段 1-6 で修正済み**で、現在は `--with_tracking` なしで stdout に出る |
| live 対話 | **未検証** | マイクを持つ人間が必要。`CLAUDE.md` の「live 対話で崩壊する checkpoint は loss に関わらず不合格」は未確認のまま |
| 明瞭度 | **未実施（測定手段はある）** | **訂正。** 撤回前は「測定手段なし」と書いた。**これは誤りである。** J-Moshi 論文自身が、生成音声を Whisper にかけ、その転写に対する日本語 LM の perplexity を fluency 指標として報告している（Interspeech 2025 §4.2）。参照テキストも参照音声も不要で、**GPU なしで実行できる**。M3 は自己参照の危険だけを見て、参照不要の方法を探さなかった。実施は M3-R 第 3 段 3-2 |
| 再現性 | **欠如** | **訂正・追加。** M3 実行時点の `generate.py` は `--seed` が既定 `None` で、生成では一度も指定していない（`args.seed is not None` のときだけ `set_seed` が呼ばれていた）。**M3-R 第 1 段 1-6 で必須化済み。**生成は **prompt あたり 1 サンプル**である。したがって崩壊件数・勝ち数・有声フレーム数・話者らしさの delta は**すべて 1 回の抽選**で、分散が測れない。M3-R は seed 固定と複数サンプルを必須にする |

## 9. 計画は機能した

不合格ではあるが、失敗したのは**実行ではなく仮説**である。

第 1 部（無課金・ローカル 18 ステップ）で **13 件の欠陥を課金前に潰した**。うち 3 件は、
気づかなければ「学習は成功したが何も測れていないデータセット」を作っていた。

| 課金前に潰した主な欠陥 | 起きていたこと |
| --- | --- |
| 話者 B が発話ごと生成では一人にならない | pairwise ECAPA 0.45〜0.52 で実人間の下限 0.565 未満。片チャンネルが群衆になる |
| 生成区間でユーザーが常に無音 | 「ユーザーを無視していないか」を無音 against 測ることになる |
| 既存の重複検出が暗記を見落とす | 学習文が逐語で丸ごと入っていても Jaccard 0.3967 で検出されない |
| `prepare_dataset` が不一致でも終了コード 0 | `&&` で繋いだスクリプトが成功として次へ進む |
| `tokenize_text` の既定 tokenizer が英語向け | 全 80 対話が skip される |

GPU 工程でも smoke test が **3 件の欠陥**を捕まえた。特に `finetune.py` は
**W&B なしでは起動すらできなかった**（`args.with_tracking` が W&B 分岐の中でのみ代入され、
最初の学習ステップ前に `AttributeError`）。この経路がこのリポジトリで一度も実行されて
いなかった理由がそれである。

採点段階でも、敵対的検証が **私の条件 3 判定の誤り**を 2 件指摘した。

- `general30` だけで判定していた（`v-real/epoch4` は general30 で無音 0/30、
  held-out と seen では 8/10）
- 無音の生成は collapse フラグをどちらも立てない。**黙るほど絶対基準を通りやすくなる**

いずれも訂正し、`degenerate_count` を追加して**無音を外して引用できない形**にした。

**ただし、規律が働いたのは実行と課金前の設計に対してであって、計器に対してではない。**
2026-08-24 の検証は、判定に使った計器のうち **3 つが壊れている**ことを突き止めた ——
基準線 control、崩壊検出器、条件 4 の一貫性基準である。
`CLAUDE.md` の「ゲートが妥当な結果を却下し続けるならゲートを疑え」が条件 4 に適用されたのは、
この検証が初めてである。修正は M3-R 第 1 段。
